## 2. Folder Responsibilities

| Folder | Responsibility | Why it exists |
|---|---|---|
| `docs/` | All planning and design deliverables (PRD, blueprint, pitch deck, this architecture set) | Keeps the repo self-documenting; anyone (including a future AI conversation) can read `docs/` and understand the whole project without asking |
| `RecoverIQ.Api/Controllers/` | HTTP endpoints — thin, just route → service/DB calls | Standard ASP.NET Core convention; keeps request handling separate from business logic |
| `RecoverIQ.Api/Models/` | EF Core entity classes (map directly to DB tables) | Single source of truth for the data shape, per `SCHEMA.md` |
| `RecoverIQ.Api/Dtos/` | Request/response shapes exposed to the frontend | Prevents leaking internal EF entities directly over the API (security + flexibility) |
| `RecoverIQ.Api/Data/` | `AppDbContext` and EF configuration | Isolates all database wiring in one place |
| `RecoverIQ.Api/Services/` | Business logic that isn't a simple CRUD passthrough — currently just AI scenario generation | Keeps `ScenarioGeneratorService` testable/mockable independent of controllers |
| `RecoverIQ.Api/Migrations/` | EF Core auto-generated migration history | Standard EF Core convention; never hand-edited |
| `recoveriq-web/src/` | All React components and API-calling logic | Flat structure — with only 7 screens (per `UI-WIREFRAMES.md`), a deeper folder hierarchy (e.g. `components/`, `pages/`, `hooks/`) would be over-engineering for this project's size |
| `scratch/` | Throwaway exploration scripts (e.g. Day 6's standalone OpenAI test) | Keeps experimental code out of the real app folders; nothing here is ever imported by the actual app |

## 3. Why This Structure (Not Something More Elaborate)

- **No `Repositories/` layer** — with EF Core and a project this size, controllers/services calling `AppDbContext` directly is simpler and appropriate; adding a repository abstraction would be unnecessary ceremony for a 10-day solo project.
- **No `components/` subfolder in React** — only 7 screens total; a flat `src/` is easier to navigate than a premature folder hierarchy.
- **`scratch/` is intentionally excluded from the "real" app** — Day 6's OpenAI prompt testing needs to happen somewhere disposable, without risking half-finished experiments leaking into `RecoverIQ.Api`.
- **Secrets never committed** — `appsettings.Development.json` and `.env` are both gitignored from day one; production secrets live in Render/Netlify environment variable settings (configured Day 8–10).
